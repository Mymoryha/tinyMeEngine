# ADR-0003：仓库知识与会话独立

- 日期：2026-11-05
- 状态：Accepted
- 关联任务：M0-001、M0-003

## 背景

项目跨度长，参与的人和 agent 会改变；聊天上下文、IDE 缓存和个人记忆不可靠。纯代码也无法解释已放弃方案和实验条件。

## 选项

- 依赖聊天与 agent 记忆：方便但无法保证可迁移。
- 先部署知识平台/复杂任务系统：成本高，且仓库与外部资料容易不同步。
- 以 Git 中的少量 Markdown 为权威，按事实类型分工，生成导览只做索引。

## 决定

选第三种：README 导航；PROJECT 管目标；ARCHITECTURE 管当前结构；ENVIRONMENT 管环境；STATE 管当前任务和交接；ADR 管决定；DEVLOG 管重要历史；实验目录管可复现结论。规则入口为 AGENTS，工程规范为 CONTRIBUTING。

文档随实现更新，重要节点必须留下“为什么”和验证证据；生成式 wiki 不覆盖人工维护的事实。完成任务不以生成文档数量衡量，而以接手者能否独立复现和继续工作衡量。

## 代价与约束

每次有效交接需要少量维护，但禁止为每个微小改名新增决策文档。权威来源不重复；链接代替复制。大捕获与二进制不进 Git，只留可复现命令和资产来源。

## 验证

接手者不依赖聊天，按 README 找到目标/状态/环境/下一步，并可验证当前骨架。里程碑关闭时检查链接和状态是否与真实代码一致。

## 重审触发

STATE 规模已无法人工维护、多并行贡献者引入外部 issue 平台、文档维护成本超过价值。迁移时先指定新唯一事实源和旧资料处理方式。
