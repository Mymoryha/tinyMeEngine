# 知识管理

## 1. 一类事实，一个权威来源

| 要找的内容 | 权威位置 | 更新时机 |
| --- | --- | --- |
| 项目目的、阶段、边界 | `PROJECT.md` | 范围或阶段出口改变 |
| 当前模块关系与契约 | `ARCHITECTURE.md` + 对应公共头文件 | 依赖、生命周期、接口改变 |
| 真实硬件、工具链、环境问题 | `ENVIRONMENT.md` | 工具升级、开发机或驱动变化 |
| 开发/验收/提交约定 | `../CONTRIBUTING.md` | 工作流改变 |
| 正在做什么、阻塞、下一步 | `STATE.md` | 每次有效交接前 |
| 为什么选择/放弃一种方案 | `Decisions/ADR-XXXX-*.md` | 关键决定形成或被推翻 |
| 重要节点发生了什么 | `DEVLOG.md` | 里程碑、接口变更、结论性修复、方案推翻 |
| 算法假设、论文、对比和失败实验 | `experiments/<id>/README.md`（首次实验时创建） | 实验可复现时，模板在 `Templates/EXPERIMENT.md` |
| 精确实现与自动契约 | 代码、测试、CMake | 随实现 |

`README.md` 仅导航。生成的 `.codewiki/` 是可重建导览，不覆盖上述权威来源。聊天记录、模型记忆、临时计划、截图和本地构建目录都不是项目唯一知识源。

## 2. 哪些知识必须落盘

满足任一项就写：

- 三个月后会问“为什么这样做”。
- 新人无法从代码推导出的限制、硬件行为、生命周期或隐含顺序。
- 公共 API / 数据布局 / shader 契约 / 模块依赖发生变化。
- 一个方向试过但失败，未来很可能重复尝试。
- 性能判断、正确性判断、已知不确定项和它们的证据。

简单改名、拼写修正不强制写 ADR 或历史。避免把每次工具调用、临时推理和整个聊天复制进文档。

## 3. ADR 规则

编号递增且不复用。记录：状态、背景、约束、候选方案、决定、收益/代价、验证方式、重审触发条件、关联任务。状态为 `Proposed`、`Accepted`、`Superseded` 或 `Rejected`。

改变已接受决策时创建新 ADR，旧 ADR 标注被谁替代并保留原结论；不能改写历史伪装成从未选择过旧方案。当前有效选择仍同步到架构或环境文档。索引只索引，不复制全文。

## 4. 任务与交接

`STATE.md` 是轻量任务板，不再建立第二个 `TODO.md`。任务最小字段：ID、状态、目标、范围、验收、依赖/阻塞。状态：`Ready → In Progress → Done`，或 `Blocked / Deferred`。个人项目默认仅一个活动任务。

结束会话前更新：

1. 当前完成到哪里，哪些还只是计划。
2. 修改范围与关键取舍（链接 ADR / 代码，不重复抄写）。
3. 实际验证命令、配置、结果；未运行项及原因。
4. 剩余风险、下一条具体行动及通过标准。
5. 基准提交或明确写“尚无提交”；若工作区含未提交修改说明是否已验证。

长期进度保留在 DEVLOG 和 Git；STATE 只保留当前里程碑与下一步，完成后压缩过期细节。外部 issue 系统将来可接入，但必须先约定谁是唯一任务事实源。

## 5. 证据与可复现性

渲染实验记录代码版本、是否有未提交修改、配置、场景/资产、随机种子、分辨率、相机、GPU/驱动、shader 版本、预热与采样窗口、正确性参照。CPU 时间不能冒充 GPU 时间；开启验证层和关闭验证层的结果不得混报。

小型文本摘要进 Git；大资源、PIX/RenderDoc 捕获、视频与输出图片放忽略的 `out/` 或外部存储。文档保留可定位的路径/标识、校验值、生成命令、必要的获取方式；不能只写“看我桌面的文件”。公开引用记录标题、来源链接、访问日期和适用结论，不把未核实假设写成事实。

## 6. 防漂移

修改代码时沿任务 → 决策 → 架构 → 测试 → 交接检查关联。每个里程碑关闭前检查文档链接、过期状态、未决 ADR、已接受技术债与复现命令。发现文档与代码冲突，先确认真实行为，再同时修正文档/实现；禁止静默选择一个版本。
